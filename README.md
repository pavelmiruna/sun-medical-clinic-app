# Sun Medical

Full-stack web application for managing a family medicine clinic. It covers the full doctor–patient workflow: appointment scheduling with real-time availability, consultations, prescriptions and referrals issued as PDFs, vaccination records, clinic announcements, automated email notifications, and AI-generated medical summaries.

Built as a bachelor's thesis at the Bucharest University of Economic Studies (ASE), Faculty of Cybernetics, Statistics and Economic Informatics.


## Features

**Role-based access (RBAC)** with four roles, each with its own interface:

- **Admin**: manages staff accounts, assigns nurses to doctors, configures clinic details and document serial prefix
- **Doctor**: weekly schedule, appointments, patient records, consultations, prescriptions, referrals, vaccinations, announcements, AI insights
- **Nurse**: operates in the context of the assigned doctor; manages appointments, creates patient profiles, issues documents, publishes announcements
- **Patient**: views appointments, consultations, prescriptions, referrals, vaccinations and documents; books or cancels appointments; manages family profiles as guardian or proxy; uses the AI assistant

**Core functionality**

- **Appointment scheduling** with slot availability computed from the doctor's weekly schedule; double booking is prevented both in application logic and by a database `UNIQUE(doctorId, scheduledAt)` constraint
- **Automated jobs** (node-cron): hourly email reminders 24h before appointments, and automatic `NO_SHOW` marking of missed appointments every 15 minutes
- **Consultations** with structured clinical fields, created atomically together with the appointment status update; supports walk-in consultations
- **Prescriptions and referrals** with a DRAFT → FINALIZED → CANCELED lifecycle, immutable finalized content, versioning, and atomic serial numbers generated by a SQL upsert
- **PDF generation** with Puppeteer: snapshot of source data → generated content → HTML template → A4 PDF
- **Patient profile claim flow**: staff create a profile, the patient claims it with a one-time code (hashed in the database, expires after 72 hours)
- **Vaccination records** and **announcements** targeted by audience (all users, patients, doctors, nurses, staff, a doctor's own patients or nurses), with email notifications
- **Transactional emails** (Nodemailer): appointment confirmation, reminders, announcements, claim codes
- **AI features** (Google Gemini API, with automatic fallback between model versions): patient record summary, patient chatbot based on the patient's own record, and clinic analytics with recommendations

## Architecture

Client–server architecture: a React SPA communicates with an Express REST API using JWT-authenticated requests. PostgreSQL is accessed only through Prisma. PDF generation, email, AI and scheduled jobs are independent modules inside the backend.

Middleware order on protected routes: `requireAuth` → `requireRole` → `validateBody` → controller. Business-rule validation (email and CNP uniqueness, password complexity) happens in the service layer.

The database schema has 15 tables grouped into: Users and Organization, Patients and Access, Appointments and Consultations, Medical Documents, and Supplementary Features (vaccinations, announcements, document counter).
